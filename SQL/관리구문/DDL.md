## **5.3 DDL**

DDL(Data Definition Language)은 데이터 정의 언어로, 데이터베이스의 구조(스키마)를 정의하고 관리하는 SQL 명령어이다.

ERD로 표현된 데이터 모델링은 논리적 모델링으로, 엔터티와 속성, 관계를 특정 DBMS에 의존하지 않는 형태로 설계하는 과정이다. 이후 DDL을 사용하여 이를 특정 DBMS에 실제 적용하는 과정은 물리적 모델링이라고 할 수 있다.

DDL을 사용하여 테이블을 생성할 때 지정해야 하는 요소는 다음과 같다.

|요소|설명|
|—|—|
|테이블 이름|테이블의 이름을 지정한다.|
|칼럼 이름|테이블을 구성하는 칼럼의 이름을 지정한다.|
|칼럼 데이터 타입|각 칼럼이 저장할 데이터의 타입을 지정한다.|
|칼럼 데이터 크기|각 칼럼이 저장할 데이터의 크기를 지정한다.|
|제약조건(Constraints)|PK, NOT NULL 등 칼럼이 가져야 할 제약조건을 지정한다.|

---

### **1. CREATE**

테이블을 생성하는 명령어이다.

```sql
CREATE TABLE 테이블명 (
    칼럼명 데이터타입[(크기)]
    [DEFAULT 기본값]
    [NULL / NOT NULL],
    ...
    [, CONSTRAINT 제약조건명 PRIMARY KEY (칼럼명)]
    [, CONSTRAINT 제약조건명 FOREIGN KEY (칼럼명)
       REFERENCES 참조테이블(참조칼럼)]
);
````

* 지정한 이름의 테이블을 생성한다.
* 동일한 이름의 테이블이 이미 존재하는 경우 오류가 발생한다.
* 하나의 테이블에는 여러 개의 칼럼을 정의할 수 있으며, 각 칼럼명은 테이블 내에서 유일해야 한다.
* `DEFAULT`는 칼럼의 기본값을 지정한다. 데이터 삽입 시 특정 값이 입력되지 않으면 지정한 기본값이 저장된다.
* `CONSTRAINT`는 PK, FK 등의 제약조건을 지정할 때 사용한다.
* 논리적 모델링에서 설계한 관계(Relationship)는 DDL에서 FK 형태로 표현된다.

#### **CREATE 문 작성 시 주의사항**

1. 테이블 이름은 해당 데이터베이스 내에서 고유해야 한다.
2. 칼럼 이름은 해당 테이블 내에서 고유해야 한다.
3. 칼럼명과 데이터 타입은 필수로 지정해야 한다.

   * 데이터 크기는 데이터 타입에 따라 필요할 수도 있고 필요하지 않을 수도 있다.
4. `DEFAULT`, `NULL`, `NOT NULL` 등은 선택적으로 지정할 수 있다.

   * 아무것도 지정하지 않은 경우 기본적으로 NULL 허용으로 처리된다.
5. 테이블 이름, 칼럼 이름, 제약조건 이름 등 식별자는 숫자로 시작할 수 없으며, 일반적으로 영문자와 숫자, 일부 특수문자(`$`, `_`, `#`)만 사용할 수 있다.
6. 칼럼 정의는 괄호 안에 작성한다.
7. 각 칼럼은 콤마(`,`)로 구분한다.
8. SQL 문은 세미콜론(`;`)으로 종료한다.
9. 테이블 이름은 의미 없이 작성하지 않고, 해당 테이블이 저장하는 데이터의 성격을 나타낼 수 있도록 작성하는 것이 좋다.
10. 칼럼 이름은 통일성을 유지해야 한다.

예를 들어 `MEMBER` 테이블과 `GUEST` 테이블에 회원번호를 저장하는 칼럼이 있다면, 하나는 `ID`, 다른 하나는 `NO`처럼 다르게 작성하지 않고 동일한 이름 규칙을 적용하는 것이 좋다.

---

### **CONSTRAINT**

`CONSTRAINT`는 칼럼에 적용되는 제약조건을 의미하며, 데이터의 무결성을 유지하기 위해 사용한다.

지정할 수 있는 주요 제약조건은 다음과 같다.

---

#### **1. PRIMARY KEY**

PK(Primary Key)는 테이블의 각 행을 식별하기 위한 기본키이다.

PK로 지정된 칼럼은 다음 조건을 만족해야 한다.

* NULL 값을 가질 수 없다.
* 모든 값이 고유해야 한다(Unique).
* 자동으로 UNIQUE INDEX가 생성된다.

---

#### **2. FOREIGN KEY**

FK(Foreign Key)는 외래키로, 다른 테이블의 PK 또는 UNIQUE KEY를 참조하는 칼럼이다.

FK를 지정하면 논리적 모델링에서 정의한 관계(Relationship)를 표현할 수 있으며, 참조 무결성 제약조건을 적용할 수 있다.

##### **참조 무결성 제약조건**

참조되는 테이블을 **부모 테이블(PK)**, 참조하는 테이블을 **자식 테이블(FK)**이라고 한다.

---

#### **1) DELETE / MODIFY ACTION**

| 제약조건 | 설명 |
| --- | --- |
| CASCADE | 부모 데이터 삭제 또는 수정 시 자식 데이터도 함께 삭제 또는 수정된다. |
| SET NULL | 부모 데이터 삭제 또는 수정 시 자식 칼럼의 값을 NULL로 변경한다. |
| SET DEFAULT | 부모 데이터 삭제 또는 수정 시 자식 칼럼을 기본값으로 변경한다. |
| RESTRICT | 자식 테이블에 참조 데이터가 존재하면 부모 데이터의 삭제 및 수정이 불가능하다. |
| NO ACTION | 제약조건을 위반하는 경우 작업이 실패하고 아무런 동작도 수행하지 않는다. |

---

#### **2) INSERT ACTION**

| 제약조건 | 설명 |
| --- | --- |
| AUTOMATIC | 부모 테이블에 값이 없는 경우 PK를 생성한 후 자식 테이블에 입력한다. |
| SET NULL | 부모 테이블에 PK가 없는 경우 자식 칼럼에 NULL 값을 입력한다. |
| SET DEFAULT | 부모 테이블에 PK가 없는 경우 자식 칼럼에 기본값을 입력한다. |
| DEPENDENT | 부모 테이블에 PK가 존재하는 경우에만 자식 테이블의 입력을 허용한다. |
| NO ACTION | 제약조건 위반 시 작업이 실패하고 아무런 동작도 수행하지 않는다. |

---

#### **3. UNIQUE KEY**

UNIQUE KEY는 PK와 마찬가지로 해당 칼럼의 모든 값이 고유해야 하는 조건을 지정한다.

다만 PK와 달리 **NULL 값을 허용한다.**

---

#### **4. NOT NULL**

해당 칼럼이 NULL 값을 가질 수 없도록 제한하는 제약조건이다.

`NOT NULL` 제약조건이 지정된 칼럼에 NULL 값을 입력하려고 하면 오류가 발생한다.

---

#### **5. CHECK**

칼럼이 가질 수 있는 값을 특정 조건이나 범위로 제한하는 제약조건이다.

예를 들어 `GENDER` 칼럼이 존재하고, 해당 칼럼이 `'M'`, `'F'` 두 가지 값만 가질 수 있도록 제한하려면 다음과 같이 작성한다.

```sql
CONSTRAINT CHK_GENDER CHECK(GENDER IN ('M', 'F'))
````

---

### **2. ALTER**

ALTER는 이미 생성된 테이블의 스키마를 변경하는 명령어이다.

---

#### **1) 칼럼 추가**

```sql
ALTER TABLE 테이블명
ADD 칼럼명 데이터타입[(데이터크기)];
```

* 기존 테이블에 새로운 칼럼을 추가한다.
* 추가된 칼럼은 기존 칼럼들의 마지막에 위치한다.

---

#### **2) 칼럼 삭제**

```sql
ALTER TABLE 테이블명
DROP COLUMN 칼럼명;
```

* 지정한 칼럼을 삭제한다.
* ALTER를 통해 삭제한 칼럼은 복구할 수 없으므로 주의해야 한다.

---

#### **3) 칼럼 변경**

```sql
ALTER TABLE 테이블명
MODIFY (
    칼럼명 데이터타입[(데이터크기)]
    [DEFAULT 기본값]
    [NULL / NOT NULL]
);
```

칼럼의 데이터 타입, 크기, 기본값, NULL 허용 여부 등을 변경할 수 있다.

##### **칼럼 변경 시 주의사항**

* 칼럼에 저장된 데이터가 없는 경우에만 데이터 타입 변경이 가능하다.
* 데이터 크기를 줄이는 경우 기존 데이터가 변경된 크기에 저장 가능한 경우에만 가능하다.
* `DEFAULT` 값을 지정하면 변경 이후 추가되는 데이터부터 적용된다.
* `NOT NULL`로 변경하려면 해당 칼럼에 NULL 값이 존재하지 않아야 한다.

---

##### **SQL Server의 칼럼 변경**

SQL Server에서는 칼럼 변경 시 `ALTER COLUMN`을 사용한다.

```sql
ALTER TABLE 테이블명
ALTER COLUMN 칼럼명 데이터타입[(데이터크기)]
[NULL / NOT NULL];
```

SQL Server는 여러 칼럼을 동시에 변경하는 구문을 지원하지 않는다.

---

#### **4) 칼럼 이름 변경**

```sql
ALTER TABLE 테이블명
RENAME COLUMN 기존칼럼명 TO 변경칼럼명;
```

기존 칼럼의 이름을 변경한다.

---

#### **5) 제약조건 추가**

```sql
ALTER TABLE 테이블명
ADD CONSTRAINT 제약조건명 제약조건(칼럼명);
```

기존 테이블의 칼럼에 새로운 제약조건을 추가한다.

---

#### **6) 테이블 삭제**

```sql
DROP TABLE 테이블명 [CASCADE CONSTRAINTS];
```

테이블을 삭제한다.

다른 테이블에서 해당 테이블을 참조하고 있는 경우 `CASCADE CONSTRAINTS`를 사용하지 않으면 삭제할 수 없다.

> SQL Server에서는 `CASCADE CONSTRAINTS` 옵션을 사용할 수 없으므로, 테이블 삭제 전에 참조 관계를 제거해야 한다.

---

#### **7) 테이블 초기화**

```sql
TRUNCATE TABLE 테이블명;
````

`TRUNCATE`는 테이블의 데이터만 삭제하고 스키마 구조는 유지하는 명령어이다.

* 테이블을 생성한 초기 상태로 되돌린다.
* 데이터는 삭제되지만 테이블 구조(스키마)는 유지된다.
* `DELETE`와 달리 롤백(ROLLBACK)이 불가능하다.
* 저장 공간이 릴리즈(Release)된다.
* DDL 명령어이므로 자동 커밋된다.

---

#### **DROP / TRUNCATE / DELETE 비교**

| 구분                           | DROP                | TRUNCATE                                  | DELETE                                            |
| ---------------------------- | ------------------- | ----------------------------------------- | ------------------------------------------------- |
| 문법                           | `DROP TABLE 테이블명`   | `TRUNCATE TABLE 테이블명`                     | `DELETE FROM 테이블명`                                |
| SQL 종류                       | DDL                 | DDL                                       | DML                                               |
| 동작                           | 테이블과 스키마를 완전히 삭제한다. | 테이블을 생성 초기 상태로 초기화한다.<br>(데이터 삭제, 스키마 유지) | 스키마는 유지하고 데이터를 삭제한다.<br>`WHERE`절을 사용하여 특정 행 삭제 가능 |
| 자동 커밋 여부                     | ○                   | ○                                         | ×                                                 |
| 디스크 공간 릴리즈                   | ○                   | ○                                         | ×                                                 |
| 작업 취소(UNDO)를 위한 로그 데이터 생성 여부 | ×                   | ×                                         | ○                                                 |
