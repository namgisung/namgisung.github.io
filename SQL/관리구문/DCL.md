## **5.4 DCL**

DCL(Data Control Language)은 데이터 제어 언어로, 사용자를 생성하고 데이터베이스 접근 권한을 부여 및 회수하는 작업을 수행하는 SQL 명령어이다.

----

### **1. USER 관련 명령어**

데이터베이스를 생성한 후 데이터를 읽고 쓰기 위해서는 계정(USER)이 필요하다.

USER 관련 명령어는 계정을 생성하고 변경하며 삭제하는 작업을 수행한다.

#### **1. USER 생성**

```sql
CREATE USER 사용자1 IDENTIFIED BY 패스워드1;
````

* `사용자1`이라는 이름의 USER를 생성하고, `패스워드1`을 비밀번호로 설정한다.

#### **USER 변경**

```sql
ALTER USER 사용자1 IDENTIFIED BY 패스워드1;
```

* 이미 생성된 `사용자1`의 비밀번호를 `패스워드1`으로 변경한다.

#### **USER 삭제**

```sql
DROP USER 사용자1;
```

* `사용자1`이라는 USER를 삭제한다.

---

### **2. 권한 관련 명령어**

데이터베이스에 접근하기 위해서는 적절한 권한이 필요하다.

권한 관련 명령어는 데이터베이스에 대한 읽기, 쓰기 등의 접근 권한을 부여하거나 회수하는 작업을 수행한다.

#### **1. GRANT**

```sql
GRANT 권한1 [ON 테이블1] TO 사용자1 [WITH GRANT OPTION];
```

* `사용자1`에게 `권한1`을 부여한다.
* 특정 테이블에 대해서만 권한을 부여하려면 `ON` 옵션을 추가한다.
* `WITH GRANT OPTION`을 추가하면 권한을 부여받은 사용자가 다른 사용자에게 동일한 권한을 부여할 수 있다.
* 지정할 수 있는 권한은 DBMS에 따라 다양하며, 대표적으로 테이블 생성 권한을 부여하는 경우 다음과 같이 작성한다.

```sql
GRANT CREATE TABLE TO 사용자1;
```

[권한의 종류]

| 권한               | 설명                               |
| ---------------- | -------------------------------- |
| CREATE USER      | 사용자를 생성할 수 있는 권한                 |
| ALTER USER       | 생성된 사용자의 정보를 변경할 수 있는 권한         |
| DROP USER        | 생성된 사용자를 삭제할 수 있는 권한             |
| CREATE SESSION   | 데이터베이스에 접속할 수 있는 권한              |
| ALTER SESSION    | 데이터베이스 접속 상태에서 환경 값을 변경할 수 있는 권한 |
| CREATE TABLE     | 자신의 스키마에 테이블을 생성할 수 있는 권한        |
| CREATE ANY TABLE | 다른 스키마 소유의 테이블을 생성할 수 있는 권한      |

#### **2. REVOKE**

```sql
REVOKE 권한1 [ON 테이블] FROM 사용자1 [RESTRICT / CASCADE];
```

* `사용자1`에게 부여했던 `권한1`을 회수한다.
* 특정 테이블에 대한 권한만 회수하려면 `ON` 옵션을 추가한다.
* `RESTRICT`는 회수하려는 권한이 다른 권한에 의존하는 경우 권한 회수를 수행하지 않는다.
* `CASCADE`는 해당 권한뿐만 아니라 의존 관계에 있는 다른 권한까지 함께 회수한다.

테이블 생성 권한을 회수하는 경우 다음과 같이 작성한다.

```sql
REVOKE CREATE TABLE FROM 사용자1;
```

### **3. ROLE 관련 명령어**

계정에 부여할 수 있는 권한은 종류가 매우 많기 때문에, 각각의 사용자에게 필요한 권한을 하나씩 부여하는 것은 데이터베이스 관리 측면에서 비효율적이다.

따라서 일반적으로 여러 권한을 하나의 패키지처럼 묶어서 관리하며, 이렇게 권한을 묶어놓은 것을 **ROLE**이라고 한다.

ROLE을 사용하면 여러 권한을 하나의 단위로 관리할 수 있어 사용자 권한 관리가 더욱 편리해진다.

ROLE을 생성하고 사용하는 과정은 다음과 같다.

#### **1. ROLE_MGR이라는 ROLE을 생성한다.**

```sql
CREATE ROLE ROLE_MGR;
````

#### **2. 생성된 ROLE_MGR에 필요한 권한을 부여한다.**

```sql
GRANT CREATE SESSION, CREATE TABLE, CREATE USER 
TO ROLE_MGR;
```

* `CREATE SESSION` : 데이터베이스 접속 권한
* `CREATE TABLE` : 테이블 생성 권한
* `CREATE USER` : 사용자 생성 권한

#### **3. ROLE_MGR을 USER1 사용자에게 부여한다.**

```sql
GRANT ROLE_MGR TO USER1;
```

**4. 이제 USER1은 ROLE_MGR에 포함된 권한을 사용할 수 있다.**

즉, USER1은 세션 연결, 테이블 생성, 사용자 생성 권한을 가진 관리자 역할의 계정이 된다.
